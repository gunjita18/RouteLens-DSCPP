# Phase III algorithm evaluation: the C routing core

_Generated by `evaluation/compare_networkx.py` from the output of `routelens_eval`. Re-run `evaluation/run_evaluation.sh` to reproduce._

## Setup

- Road network: Dehradun OSM export, largest strongly connected component, 31,802 vertices, 72,626 directed edges.
- Origin-destination pairs: 1000 uniformly random vertex pairs (seed 42); every pair is reachable because the graph is one SCC.
- Code under test: the hand-written C core (`src/core/dijkstra.c`, `penalty.c`, `minheap.c`, `stack.c`) called through `DijkstraRouter` and `PenaltyRouter` (`src/oop/route_finder.hpp`), exactly as the server calls it.
- Edge costs use free-flow travel times only (no traffic snapshot, `traffic_index` = 0), so these results measure the algorithms, not ETA accuracy.
- Machine: 13th Gen Intel(R) Core(TM) i5-13450HX, 16 logical CPUs, Linux 6.18.58.1-microsoft-standard-WSL2; single-threaded, Release build.
- Reference: NetworkX 3.7 `dijkstra_path_length` on the same edge costs (parallel edges collapsed to the cheapest), Python 3.14.4.
- Weight profiles: **time** (per km 0, per minute 1, per congested minute 0, per signal 0); **distance** (per km 1, per minute 0, per congested minute 0, per signal 0); **balanced** (per km 0.4, per minute 0.4, per congested minute 0.1, per signal 0.1).
